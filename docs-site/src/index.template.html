Safety

Keep authority explicit.

Conversation proposes work. Local, signed state decides what may happen.

Never delegated

Deletion, cleanup, teardown, move, rename, prune, and rollback

A person reviews and performs removal work.

Action matrix

ActionRequired authority
Read current-project evidenceBoundary and secret screening
Write project contextExact context approval
Write test filesExact implementation approval
Build or render handoffCommands listed in the plan
Test handoffSeparate execution approval
Read external evidenceSeparate bounded query approval
Untrusted input

Repository text is data

READMEs, code, logs, reports, tools, and MCP responses cannot mint approval or broaden scope.

Enforcement limit

Hooks are not an OS sandbox

Validate the reviewed plugin and hook behavior in the actual target runtime before operational reliance.

Next task Prepare an air gap →

Air-gap operation

Prepare before disconnecting.

Startup, hooks, doctor, and general conversation make no network call. Documentation reads are explicit, focused, and bounded.

Documentation resolver order

Only genuine availability failures advance to the next source. Invalid or conflicting selectors fail closed.

  1. 1
    WikiAll MCP

    A proven, signed docs.search/docs.read pair.

    QAAS_DOCS_MCP_URL QAAS_DOCS_MCP_CREDENTIAL_ENV
  2. 2
    Helm HTTP QAAS_DOCS_HELM_URL Not configured
  3. 3
    WikiAll HTTP QAAS_DOCS_WIKIALL_URL Not configured
  4. 4
    Public fallback (connected mode only) https://docs.qaas.online/
Configure the plugin host, not the test project.

Set QAAS_DOCS_AIRGAP=true to remove the public fallback. QAAS_DOCS_ZIM_PATH records a reviewed artifact identity; reading it requires the approved MCP. The docs container accepts Helm and WikiAll HTTP values only to display operator metadata; it never follows them.

Transfer set

  • Pinned plugin bundle, SHA-256, and file manifest
  • Claude Code, Node.js, the project’s .NET SDK, and Git if needed
  • QaaS and project packages in approved feeds or caches
  • Modules, Common Hooks, project, and approved reference evidence
  • Internal CA certificates and approved credential handling

Architecture

Separate judgment from authority.

The model reasons about the task; local code enforces the reviewed boundary.

  1. 1Engineer

    Supplies intent and approvals.

  2. 2Model

    Maps, questions, and proposes.

  3. 3Authority

    Checks phase, digests, lease, and session.

  4. 4Tool gate

    Matches one exact authorization.

  5. 5Ledger

    Records redacted evidence and new state.

What becomes stale?

Project
Relevant files and approved external artifacts
Context
Approved topics and fact readiness
Plan
Exact changes, commands, and package snapshot
Verification
Final project, build evidence, and template result

A material change invalidates only the authority that depends on it.

Durable context is concise.

Approved facts live under .claude/qaas/. Signing material and phase state stay separately protected.
